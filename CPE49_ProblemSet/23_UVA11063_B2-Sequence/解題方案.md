# 解決方案

先檢查數列是否為正整數且嚴格遞增，再枚舉所有 `i ≤ j` 的配對，使用 `unordered_set` 記錄已經出現過的兩數之和。

如果發現某個和已經存在，代表不同配對得到相同結果，這個數列就不是 B2-Sequence。全部檢查通過，才符合條件。

## 具體操作：

持續輸入數列長度 `n`，直到檔案結尾。每筆測資先將 `is_b2` 設為 `1`，並建立 `vector<int> vec(n + 1)` 與空的 `unordered_set<int> ust`。

程式使用從 `1` 索引，輸入時將數字存入 `vec[1]` 到 `vec[n]`。由於建立 `vector` 時各個元素會初始化為 `0`，所以 `vec[0]` 可以作為第一個元素的比較基準。

每讀入一個數字，就檢查 `vec[i] <= vec[i - 1]` 是否成立。當迴圈初始化時 `i = 1`，這個設可以協助後續，判斷檢查數組是否為嚴格遞增(包含第一個數字是否嚴格遞增於`0`)。若不符合，就將 `is_b2` 設為 `0`，但仍要讀完整筆數列避免干擾下一筆測資輸入。

如果數列通過前面的檢查，就使用兩層迴圈，外層 `i` 從 `1` 到 `n`，內層 `j` 從 `i` 到 `n`，計算 `vec[i] + vec[j]`。

使用 `ust.find(vec[i] + vec[j])` 檢查這個和是否已經出現。如果找不到，就將它加入 `ust`；如果已經存在，就將 `is_b2` 設為 `0`，並停止剩餘配對的檢查。

最後依照 `is_b2` 輸出對應結果，測資編號從 `1` 開始，每筆輸出後再留一個空白行。

## 複雜度

設 `n` 為輸入數列的元素數量。

- **時間複雜度：平均 O(n²)**。讀取與檢查數列需要 `O(n)`，最多枚舉 `n(n + 1) / 2` 個組合；`unordered_set` 的查找與插入平均為 `O(1)`，因此整體平均為 `O(n²)`。

- **空間複雜度：O(n²)**。`vector` 儲存 `n + 1` 個元素，`unordered_set` 最多記錄 `n(n + 1) / 2` 個不同的和，整體為 `O(n²)`。

## 備註：

時間複雜度採用雜湊表操作的平均情況分析，並非保證每次查找與插入都只需要固定時間。

此題為我的解題方案中較為少見的`1`索引，之所以採取`1`索引主要考量到可以在輸入前面插入一個`0`來確保檢查嚴格遞增可以更方便檢查，且可以順便把第一個元素是否為非正整數的檢查合併到遞增檢查中，以此減少代碼的撰寫量。

關於`unordered_set`這個STL的於這題的使用，我個人是習慣使用unordered_map來操作在空間上不會有太大的差距時間上幾乎相同，因為unordered_map的可擴展性較高，所以之後有用到類似的內容可能都是以unordered_map為主。
