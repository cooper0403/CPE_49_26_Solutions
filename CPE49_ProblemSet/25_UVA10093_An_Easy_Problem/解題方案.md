# 解決方案

先建立字元到數值的對照表，再找出輸入中最大的數字值。進位制必須大於這個值，且至少為 `2`。

從最小合法進位制到 `62`，依序測試候選進位制 `N`，計算該進位制下整個數字對 `N - 1` 的餘數。找出第一個餘數為 `0` 的進位制，就是答案。

每讀入一個數字字元，就將目前餘數乘上進位制，再加上該字元的數值並取餘數，因此不需要將整個數字轉成整數。

## 具體操作：

使用 `unordered_map<char, int> um` 建立對照表：`1` 到 `9` 對應 `1～9`、`A` 到 `Z` 對應 `10～35`、`a` 到 `z` 對應 `36～61`。字元 `0` 透過 `operator[]` 的預設值取得 `0`。

先設定 `base = 2`，走訪字串並執行 `base = max(um[it] + 1, base)`，取得最小合法進位制。

建立 `vector<int> vec(63 - base)`，初始值皆為 `0`，其中 `vec[j]` 記錄進位制 `N = base + j` 的餘數，候選範圍包含 `base` 到 `62`。

使用兩層迴圈走訪每個字元與每個候選進位制，更新 `vec[j] = (vec[j] * (base + j) + um[str[i]]) % (base + j - 1)`。

最後由小到大走訪 `vec`，遇到第一個餘數為 `0` 的位置就輸出 `i + base`；若全部都不符合，就輸出 `such number is impossible!`，最後換行。

## 複雜度

設 `n` 為輸入字串長度，`k` 為候選進位制數量。

- **時間複雜度：O(nk)**。每個字元都需更新各候選進位制的餘數；`k` 最多為 `61`，因此也可視為 O(n)。

- **空間複雜度：O(n + k)**。使用字串儲存輸入、`vector` 儲存餘數，字元對照表的大小有固定上限。

## 備註：

此題通過UVa OJ與瘋狂程設的測試，其中瘋狂程設的限制較鬆可能會在特定情況下給予錯誤代碼通過之判斷，如遺漏了小寫的`z`照樣可通過。

若輸入帶有正負號，符號不影響能否整除；目前程式透過 `um` 的預設值 `0` 處理開頭的符號。

候選進位制由小到大排列，因此找到第一個餘數為 `0` 的位置後，就可以直接輸出答案。
